# galaxy-buds-multipoint

삼성 계정 없이도 컴퓨터에서 Galaxy Buds 멀티포인트를 쓴다.

*[English](README.md)*

Galaxy Buds2 Pro는 멀티포인트를 지원하지만, 갤럭시가 아닌 기기에서 소리가 나기
시작하는 순간 휴대폰 연결을 끊어 버린다. 흔히 나오는 설명은 삼성이 "두 기기가 같은
삼성 계정에 로그인되어 있을 때"만 멀티포인트를 허용하기 때문이며, 컴퓨터는 그 조건을
만족할 수 없다는 것이다.

진단이 틀렸다. 펌웨어는 계정보다 **버전 바이트를 먼저** 검사하고, 컴퓨터는 바로 거기서
탈락해 계정 검사까지 도달조차 하지 못한다. 그 바이트는 갤럭시 휴대폰이 페어링할 때
보내는 단 하나의 프로토콜 프레임으로 설정되며, 서드파티 클라이언트는 아무도 보내지
않는다. 한 번만 보내면 멀티포인트가 동작한다. 휴대폰과 컴퓨터가 동시에 연결되고,
계정은 전혀 관여하지 않는다.

```bash
cd macos && ./budsmp apply
```

프레임 하나, `fc0b00014304030400000b021eafcc`를 한 번 쓰는 것이 전부다. 버즈 자체
저장 영역에 남기 때문에 재연결이나 재부팅 후에도 유지되고, `./budsmp revert`로 원래
값 그대로 되돌릴 수 있다.

## 지원 현황

| 플랫폼 | 상태 |
|---|---|
| macOS | 동작 확인, 실제 기기에서 검증 |
| Linux | 예정 — `AF_BLUETOOTH` / `BTPROTO_RFCOMM` |
| Windows | 예정 — `AF_BTH` / `BTHPROTO_RFCOMM` |

Galaxy Buds2 Pro에서 개발하고 확인했다. 동작 원리는 특정 모델에 종속되지 않으므로
`SPPSERVICE4`를 광고하는 다른 Galaxy Buds에서도 통할 것으로 보이지만, 검증되지
않았다 — 제보를 환영한다.

## 원리

두 번째 기기에서 오디오가 올라오면 버즈는 두 단계 검사를 수행한다.

1. **`asVer` 게이트.** 페어링된 각 피어마다 버즈 저장 영역에 `asVer` 바이트가 있다.
   어느 한쪽이라도 `{2, 3}` 범위를 벗어나면 버즈는 둘 중 하나의 연결을 끊는다
   (이유 코드 `0xa9`).
2. **계정 게이트.** 1단계를 통과한 경우에만 도달한다. 두 피어의 삼성 계정 해시를
   비교하는데, 한쪽 피어가 "special"로 분류되면 비교 자체를 건너뛴다. 컴퓨터가 바로
   그 "special"에 해당한다.

`asVer`를 쓰는 메시지는 `SPPSERVICE4` RFCOMM 채널의 `MDE_VERSION` 하나뿐이다.
갤럭시 휴대폰은 페어링 중에 이걸 보낸다.
[GalaxyBudsClient](https://github.com/timschneeb/GalaxyBudsClient) 같은 서드파티
클라이언트는 *다른* 채널(`GEARMANAGER`)에 붙고 이 메시지를 보내지 않으므로, `asVer`가
계속 `0`으로 남아 1단계에서 영원히 걸린다.

그래서 해결책은 그 메시지 하나를 보내는 것이다. 핸들러는 `version <= 3` 외에는 아무
것도 검증하지 않는다. 서명도, 논스도, 계정 관련 데이터도 필요 없다.

계정 해시가 정말로 필요 없다는 것은 추측이 아니다. 게이트가 실제로 살아 있음을
증명하는 양성 대조군까지 포함해 실제 기기에서 검증했다. 일부러 틀린 계정을 넣어도
휴대폰은 연결을 유지했고, 계정을 0으로 밀어도 유지했으며, *올바른* 계정에 `asVer = 0`을
넣었을 때는 끊겼다. 방법과 결과는 [docs/experiments.md](docs/experiments.md)에 있다.

자세한 내용: 와이어 포맷은 [docs/protocol.md](docs/protocol.md),
펌웨어 쪽은 [docs/firmware-gate.md](docs/firmware-gate.md).

## 설치와 사용

### macOS

```bash
git clone https://github.com/id6917824/galaxy-buds-multipoint
cd galaxy-buds-multipoint/macos
./build.sh
./budsmp apply
```

Xcode 커맨드 라인 도구(`xcode-select --install`) 외에는 아무것도 필요하지 않다.
먼저 버즈를 연결하고, macOS가 블루투스 접근 권한을 물으면 **허용을 누르면 된다** —
도구는 그 응답을 기다리며 멈춰 있고, 대화상자는 다른 창 뒤에 숨기를 좋아한다.

```bash
./budsmp read      # 이 호스트에 대해 버즈가 저장한 값 확인
./budsmp revert    # 되돌리기
./budsmp --help    # 전체 명령과 옵션
```

`apply`가 채널을 열지 못하면 버즈가 자고 있는 것이다. 케이스에서 꺼내고, 오디오 출력
장치로 선택한 뒤 아무거나 재생하고 다시 시도한다. 나머지 실패 상황은
[macos/README.md](macos/README.md)에 정리해 두었다.

### 프로토콜 도구

프레임 빌더와 디코더는 Python 3만 있으면 어디서든 동작한다. 의존성은 없다.

```bash
cd python
python3 -m budsmp.frame version-only 2                         # 픽스 프레임 생성
python3 -m budsmp.frame decode fc0b00014304030400000b021eafcc   # 프레임 분해
python3 -m budsmp.frame selftest                               # 캡처한 바이트와 대조
```

## 안전한가?

버즈가 이미 컴퓨터마다 들고 있는 레코드에서, 1바이트 크기의 필드 하나를 쓴다.
구체적으로는:

- **가역적이다.** `./budsmp revert`가 원래 값을 복원한다. 재페어링은 필요 없다.
- **펌웨어를 수정하지 않는다.** 플래싱하는 것이 없다. 버즈가 광고하는 채널로
  버즈가 정상적으로 받아들이는 프로토콜 메시지를 보낼 뿐이다.
- **어디로도 전송하지 않는다.** 네트워크도, 계정도, 텔레메트리도 없다. 버즈와
  통신하는 것은 블루투스로 연결된 본인 기기뿐이다.
- **해당 호스트에만 적용된다.** 실행한 컴퓨터의 레코드만 건드린다. 휴대폰 레코드는
  수정하지 않는다.
- **버즈 초기화 후에는 사라진다.** 초기화했다면 다시 실행하면 된다.

하지 않는 일: 없는 기능을 해금하지 않고, 오디오 처리를 바꾸지 않으며, 휴대폰 쪽은
아무것도 변경하지 않는다.

현실적으로 최악의 실패는 버즈가 한쪽 기기 연결을 일시적으로 끊는 것인데, 이는 픽스
이전에 이미 하고 있던 동작이고 다음 쓰기로 되돌아간다.

## 한계

- 실행한 호스트만 고쳐진다. 컴퓨터가 두 대면 각각 실행해야 한다.
- 버즈는 활성 링크를 2개까지 유지한다. 이 픽스가 그 상한을 올려주지는 않는다.
- 오디오는 실제로 재생 중인 기기를 따라간다. 유휴 상태인 기기에서 재생을 시작해도
  다른 쪽이 멈출 때까지 스트림을 가져오지 않는다. 결함이 아니라 일반적인 멀티포인트
  중재 동작이다.
- 버즈 초기화 시 초기화된다.
- 지금은 macOS만 지원한다.

## 면책

본인이 소유한 하드웨어를, 그 하드웨어와의 상호운용을 위해 리버스 엔지니어링한 결과물이다.
이미 손에 있는 기기들이 함께 동작하도록 프로토콜 세부사항을 문서화한 것이며, 삼성의
코드는 포함하지 않는다.

본인 기기에 사용하기 바란다. 삼성과 제휴·보증·지원 관계가 없고, 보증(워런티)이 무효화될
수 있으며 펌웨어 업데이트로 동작이 멈출 수 있다. 어떠한 보증도 없이 있는 그대로
제공된다 — [LICENSE](LICENSE) 참고.

"Galaxy Buds"와 "Samsung"은 삼성전자의 상표다.

## 기여

제보하면 도움이 되는 것들:

- 다른 Galaxy Buds 모델: `budsmp scan`에 `SPPSERVICE4`가 보이는지, `apply`가
  동작하는지. 모델명과 펌웨어 버전을 함께 적어 주면 좋다.
- Linux와 Windows 전송 계층 — `python/budsmp/frame.py`의 프로토콜 계층은 완성되어
  검증까지 끝났으므로, 남은 것은 소켓 배관 작업이다.

로그를 올릴 때는 먼저 스크럽하자. `budsmp` 출력에는 본인의 블루투스 주소가 들어 있고,
`read`는 삼성 계정 해시를 출력한다.
